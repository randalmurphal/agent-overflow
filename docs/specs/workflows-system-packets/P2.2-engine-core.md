## Binding design decisions

### Runtime gate evaluator (extends `def`)

- New file(s) in `internal/workflow/def` (e.g. `evaluate.go`): pure
  evaluation of a phase's ordered route list against a variable context.
  `EvaluateGate(phase, vars, loopCounts) → (Route decision, Trace, error)`
  shape (exact signature yours). Semantics per D5, matching the validator's:
  ordered, first-match-wins, short-circuit; predicates over absent optionals
  evaluate false; only `exists` observes absence; loop routes consult
  per-gate-edge counters — an exhausted `max` falls through to the next
  route; human routes match unconditionally when reached; list exhausted
  after a loop-exhaustion → distinct outcome (engine parks
  `retries-exhausted`); list exhausted otherwise → distinct no-match outcome
  (engine parks `wiring-error`). The **trace** records every predicate
  evaluated with its result — it is persisted verbatim into the phase row's
  `gate_trace`.
- MUST NOT modify existing `def` files (parse/validate/envelope/interpolate)
  — the evaluator is additive. If evaluation seems to require changing them,
  BLOCKED.
- Variable context: workflow inputs (item seeds) + completed phase outputs
  namespaced `<phase-id>.<output>` — assembled by the engine from the item's
  seeds and persisted phase rows' output envelopes (latest completed attempt
  per phase). Loop counts derive from persisted gate traces of prior
  attempts; no separate counter state (D8).

### Engine (`internal/workflow/engine`)

- **Single engine goroutine owns every FSM transition.** External calls
  (enqueue, cancel, reorder, toggle, phase-completion callbacks) are commands
  the goroutine consumes; reads may hit the store directly. Store writes are
  short-lived calls from the engine goroutine (single-connection DB).
- **In-memory scheduler state is rebuilt from SQLite at startup**
  (discussion `RestoreDeliberation` precedent). Startup rebuild includes the
  **crash sweep** (D9): any item `running` whose current phase attempt has no
  terminal envelope runs teardown and parks `needs-human(interrupted)`.
  Never auto-re-run.
- **FSM:** queued → running → needs-human ↔ running → done | failed |
  cancelled. Every transition to failed/needs-human/cancelled carries a typed
  reason from the spec §2 closed set; transitions persist via P2.1's
  state-update CRUD before the in-memory state advances.
- **Teardown is ONE function** (D9) and the only code that releases
  semaphores: stop the turn (runner seam), release the phase's semaphores,
  persist the partial envelope on the phase row (whatever the runner hands
  back, possibly nil), transition with typed reason, emit. Every stop path —
  cancel, crash-sweep, park, later watchdog/budget/retry triggers — calls it.
  Tests must prove semaphore leak-freedom on every exit path.
- **Semaphores:** keyed (project, resource name). Capacity is read from the
  **live project profile at acquisition time** — the run snapshot pins the
  workflow's *needs* (which names it references), never the project's
  capacities (environment facts stay live; two projects never contend on the
  same name). Multi-resource acquisition in canonical (sorted-name) order,
  all-or-nothing. Phase-scoped: acquired at phase entry, released only via
  teardown/phase-exit. A capacity lowered below current holders blocks new
  acquires but never evicts holders. A phase blocked on a semaphore holds its
  item's global concurrency slot (§6) and is NOT stalled.
- **Queue semantics (D3.1):** active/paused toggle + global concurrency cap
  supplied through a small config seam (interface or struct the engine is
  constructed with; the App wires real settings in a later packet — tests
  inject). While active: drain queued items by sort_position as slots free.
  Pausing stops new starts; running items finish. Optional in-memory
  "process N then stop" bound: after N item-starts the engine flips itself
  paused (bound does not survive restart — document it). needs-human items
  hold no slot and no semaphores.
- **Phase runner seam:** the engine drives phases through an interface it
  defines (something like `Run(ctx, RunRequest) → Outcome` + `Stop(...)`) —
  implemented by P2.3 with real providers; your tests use a scripted fake
  (legitimate: the runner is a collaborator, not the subject). Outcomes the
  seam must express: envelope-done (with outputs), question, stuck,
  execution-failure (no envelope), cancelled/stopped. Gate routing consumes
  done outcomes; question/stuck park per spec §7; execution-failure parks
  `needs-human(agent-error)` in THIS packet (the retry ladder is a later
  packet — leave the seam so it can intercept).
- **Emitter seam:** engine takes an emitter interface (event name + payload)
  and emits on every state change; the app binds it to the real `workflow:*`
  channel in a later packet. Tests assert emissions.
- **No timers, no goroutine-per-item, no sleeps in tests.** Everything is
  event-driven through the command loop; tests drive completions
  synchronously via the fake runner.
- New packages get `doc.go`, `AGENTS.md` + `CLAUDE.md` symlink, and an
  `internal/AGENTS.md` layout row (engine row; def row's description extends
  with evaluation). Keep files under ~500 lines — split by concern
  (fsm/drain/semaphores/teardown/rebuild).
