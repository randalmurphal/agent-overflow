## Implemented profile format

Top-level keys:

- `base_branch` — optional default branch for new workflow items.
- `checks` — logical check names to non-empty argv lists.
- `capacities` — project-local resource names to integer capacities of at least one.
- `commands` — logical report/query command names to non-empty argv-template lists.
- `reliability` — project reliability defaults.
- `disposition` — `manual`, `auto-pr`, or `auto-merge`; omission defaults to `manual`.
- `secrets` — logical secret names to explicit env/file references.
- `mcp_servers` — MCP server names that workflows may request from this project.
- `worktree_setup` — source-workspace copy globs and ordered argv commands for later engine execution.

Nested keys:

- `reliability.watchdog` — positive `time.ParseDuration`-compatible inactivity duration.
- `reliability.per_item_budget` — optional ceiling with exactly one positive
  `tokens`, positive finite `usd`, or positive duration `wall_clock` field.
- `secrets.<name>.source` — `env` or `file`.
- `secrets.<name>.env` — required variable name for an `env` source.
- `secrets.<name>.path` — required regular-file path for a `file` source.
- `worktree_setup.copy` — non-empty glob strings, retained as declarations only.
- `worktree_setup.run` — argv lists with a non-empty executable at index zero,
  retained as declarations only.

## ASSUMPTIONS

- The spec's per-item “tokens / $ if reported, else wall-clock” ceiling is
  represented as one discriminated `per_item_budget` object with exactly one of
  `tokens`, `usd`, or `wall_clock`, rather than an ambiguous scalar.
- `mcp_servers` is a grantable list of configured server names; provider-specific
  MCP configuration remains outside this pure profile package.
- `Load` accepts the complete profile path rather than a config root and project
  slug, keeping project identity/path composition in `internal/project` and its
  future caller.
- A present empty or malformed file is an error; only filesystem absence selects
  the documented default profile.
- File-backed secret bytes are preserved exactly, including a trailing newline,
  because trimming would alter secret material without an explicit format rule.
- File-backed secrets must be regular files and are capped at 1 MiB to prevent an
  agent-editable profile from triggering unbounded reads; normal mounted secret
  files and symlinks to regular files remain supported.
- Resolved values are keyed by logical secret name. A future engine decides how
  those logical names map into phase environments or MCP configuration.
- Worktree copy globs are validated only for non-emptiness here. Safe expansion,
  workspace confinement, copying, and command execution belong to the future
  engine and are intentionally not performed by this packet.
