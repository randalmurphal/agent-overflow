## Assumptions

- The packet's bold ruling that a disposition-bearing item is resolved regardless of state takes precedence over the earlier shorthand predicate. The backend therefore requires `disposition = ''` for all unresolved states, including active-state rows, and the frontend matches it.
- `WorkflowListUnresolvedItems("")` is intentionally app-wide because the packet explicitly assigns that meaning and `WorkflowListItems` already uses the same convention.
- `WorkflowListUnresolvedItems` is LAN wire-safe for the same reason as `WorkflowListItems`: it is a read-only history projection with no privileged local surface.
- The phase-context projection includes `gate_trace` and `intervention` in addition to phase ID, attempt, status, and output envelope because `loopCounts` actually consumes those fields. It still omits the cumulative input envelope and all unrelated phase data.
- A store template is safe to copy only after the WAL is checkpointed, the database is closed, and each test opens its own copied file so connection-local PRAGMAs are reapplied.
- `projectId` on engine/app item-state events is authoritative. The frontend ignores malformed item events without it rather than performing an incorrectly scoped refresh.
- Full catalog reload remains required for transport-gap recovery even when the lost event was an item event, because the gap is a coarse resynchronization boundary; ordinary item-state refreshes never reload catalogs.
- Empty snapshots are valid for queued/unstarted detail rows and yield an empty `checkPhaseIds` array. Malformed non-empty persisted snapshots fail loudly at the backend detail boundary.
- The item-9 RPC formula excludes the conditional current-detail reload, matching the packet's stated `1+2` target and the adjudicated review's overview-wave accounting.
