## ASSUMPTIONS

- The user-provided statement that the lane baseline was already green
  satisfies the packet's pre-edit baseline prerequisite; I did not rerun a
  second pre-edit baseline after changes had begun.
- P2.1's v22 migration already contained `step_mode`, and the work-item model,
  scans, and creates already supported it. Rewriting v22 would violate the
  append-only migration rule, so v24 is a named no-op marker that verifies the
  reserved column and records when the feature begins using it.
- P1.1 already added `WorkflowOutput.Artifact` and the corresponding authoring
  schema field. This packet retains those existing definitions and adds the
  runtime validation and capture behavior rather than duplicating or
  rewriting them.
- `WorkflowEnqueueItem`, its transport registration, and its LocalOnlyMethods
  classification already existed. Regenerating bindings after adding the
  parameter was required; adding a second registration entry was not.
- A profile copy source uses Go `filepath.Glob` semantics. Recursive `**` is
  not invented, and a pattern matching nothing is a visible setup failure.
- Setup copy sources and destination ancestors must not contain symlinks.
  Rejecting symlinks is the clearest confinement guarantee for config copied
  from a user repository, and `.git` is excluded even when reached through a
  wildcard.
- `worktree_setup.timeout` covers the complete sequential `run` command
  sequence. Copy work observes the runner's parent cancellation but is not
  charged to the authored command-sequence timeout.
- Hooks normally run once, during fresh provisioning. If the process crashes
  after worktree creation and hooks but before metadata persistence, the only
  durable evidence is the registered item-prefixed worktree; recovery reuses
  it and reruns hooks before persisting. Exact-once execution across that crash
  window would require additional durable state outside this packet.
- Rollback removes the newly created worktree but deliberately preserves its
  unlanded branch, matching the packet invariant that such a branch is never
  silently discarded.
- Artifact output values are relative paths to regular files. Directories,
  absolute paths, escaping paths, symlinked paths, missing files, and outputs
  not produced by the completing phase fail visibly.
- The retained artifact filename is the declared output name plus the source
  file's final extension. Re-capture replaces stale extensions for that output
  and the listing exposes only completed files.
- Windows desktop execution enters through the existing WSL launcher, so the
  native Windows setup-command helper uses standard cancellation and
  `WaitDelay`; Unix/WSL execution additionally kills the full process group.
- Cleanup remains inert for read-only workflows and writing workflows. Even
  `cleanup: auto` cannot discard a worktree until disposition lands in M3.
- Generated bindings were produced with `wails3 generate bindings -clean=true
  -ts`; no generated binding was edited by hand.

## Provisioning state machine

- **Project-root:** derive workspace need from the frozen workflow. A
  read-only workflow returns the project's root immediately, performs no
  work-item reload, creates no branch, and runs no worktree hooks.
- **Fresh writing item:** load the current item and profile, resolve the
  configured base branch (or the repository default through the existing git
  convention), create an item-prefixed generated branch and
  `defaultWorktreePath`-layout worktree through `internal/git`, copy setup
  inputs, run setup commands, then atomically persist worktree path, branch,
  and base branch before creating the phase thread.
- **Interrupted fresh provisioning:** if item fields remain empty but exactly
  one registered worktree has the workflow/item-specific branch prefix,
  recover that worktree rather than cutting another branch, rerun setup, and
  persist it. Zero matches provisions normally; multiple matches fail visibly
  instead of guessing.
- **Reuse:** when all three persisted fields are present, require the directory
  and matching registered branch to exist, then reuse the same worktree for
  every later phase and resume attempt without rerunning hooks.
- **Missing or inconsistent worktree:** partial metadata, a missing directory,
  or a registration/branch mismatch returns `ErrSetupFailed`; the engine parks
  the item as `needs-human(setup-failed)` and never silently recuts it.
- **Rollback:** creation, setup, or persistence failure removes a worktree
  created or recovered by this provisioning attempt through the existing git
  core. Removal failure is joined into the surfaced error. The branch is
  retained.

Provisioning, hook execution, and filesystem copies run on a runner-start
worker. Runner entry is acknowledged immediately, while completion is keyed
back through the engine command loop. Cancel, status, and unrelated items
therefore remain responsive while a setup command is blocked.

## Step-mode semantics

- When an automatic gate evaluates to `advance`, `loop`, `done`, or `failed`,
  the phase completion and trace are persisted with that exact decision. A
  step-mode item does not execute it immediately; it parks as
  `needs-human(gate)`.
- Approve records a human intervention and executes the persisted decision
  through the existing continuation path. It does not reevaluate or rewrite
  the route.
- Reject returns exactly: `step gates support approve; use cancel, resume, or
  take over`. There is no invented reject route.
- A workflow-authored `DecisionHuman` gate retains its existing approve/reject
  behavior and is not treated as a step park.
- Rebuild restores the last persisted decision and its feedback context, so a
  crash between park and approve resumes the same continuation.

## Artifact resolution rules

- Capture is considered only after a successful phase attempt has reached
  `done`.
- A workflow output qualifies when `artifact: true`, its `from` expression
  resolves to a string output variable, and that variable belongs to the phase
  that just completed. Plain values and outputs produced by other phases are
  not copied.
- The value must name a confined workspace-relative regular file. Validation
  rejects absolute and escaping paths, symlinks in the path, missing files,
  directories, `.git` traversal, and destination escapes. Root-relative file
  operations use `os.Root` so a path cannot be swapped outside the workspace
  between validation and copy.
- Files are staged outside the visible artifact directory and atomically
  renamed to `<data-root>/workflow-runs/<item-id>/artifacts/<output-name><ext>`.
  This intentionally follows the P2.4 `workflow-runs/<item-id>` layout instead
  of D13's illustrative `runs/<run-id>` path.
- A capture failure emits a sanitized `workflow:error` naming the output,
  writes the detailed cause to the local log, continues other outputs, and
  never changes the authoritative phase outcome or envelope.
- `WorkflowGetItem` derives a deterministic, deduplicated listing from the
  artifact directory with name, path, size, and modification time; staging
  files are never listed.

## Post-task review

The required six-lens parallel review was run for performance and memory,
maintainability, architecture, testing, security, and codebase consistency.
Validated findings fixed before the final gates included:

- moving blocking `Runner.Start` provisioning off the engine owner loop while
  retaining keyed startup results, cancellation, and deterministic `Sync`;
- preventing one blocked item startup from delaying another item's commands;
- killing timed-out Unix setup-command descendants, not just the shell;
- moving artifact copying off the provider event loop;
- avoiding redundant work-item/project reads on the read-only path;
- persisting phase completion before the step intervention and rebuilding its
  feedback context for crash safety;
- closing source and destination symlink/TOCTOU escapes with `os.Root`;
- excluding `.git` after glob expansion and directory walking;
- sanitizing artifact errors sent over the transport while retaining detailed
  local diagnostics;
- recovering a registered item worktree after interruption before metadata
  persistence; and
- hiding partial artifact staging files and deduplicating stale extensions.

No unresolved review finding required a product-behavior decision or an
out-of-scope architectural change.
