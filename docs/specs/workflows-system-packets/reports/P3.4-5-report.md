## Event → store reaction map

| Event | Reaction |
|---|---|
| `workflow:item-state` | Validate identity/state; optimistically patch list and open detail state/reason, then coalesced-refetch only that open detail (and an already-requested diff). |
| `workflow:queue-state` | Patch the lightweight header overlay only; no project fan-out/refetch. |
| `workflow:phase-state` | Refetch only when that item is the active run detail; burst requests coalesce. |
| `workflow:error` | Trim to 240 chars, dedupe by `itemId+message`, cap dedupe memory at 100, and toast user-facing state. |

All four subscriptions are cancelled by `setupEventListeners` teardown.

detail, parsed diff, receipts, intake, and timer state.

## Assumptions and constrained findings

1. `def.Variable`/canonical JSON schema currently has no `default` or
   `multiline` authoring property. The mandated distilled fields remain optional
   and absent/false until the definition model gains them; no raw schema is
   exposed.
2. The enqueue RPC has no base-branch override parameter. Intake shows the
   profile catalog base branch read-only and sends the exact existing enqueue
   signature.
3. Named value outputs are not present in `WorkflowItemDetail`; the Outputs
   block renders file artifacts only.
4. Check phases are shown only when the frozen snapshot cleanly identifies a
   tool phase with a string `check`; malformed/ambiguous snapshots omit the row.
5. Artifact activation uses existing LocalOnly `OpenInEditor`; no forbidden
   review/preview companion wiring was added.
6. Automation data has no listing RPC. Scheduled/next-run chrome remains behind
   `hasAutomation = false`; the notes component and data path exist but are
   inert.
7. Remote workflows remain LocalOnly under Amendment 2. P3.6 owns the coherent
   read reclassification and remote mutation gating.
8. Persisted `json.RawMessage` reaches tests/runtime as either a JSON string or
   an already-decoded object, so parsers accept both while schema-checking the
   receipt/digest fields.
9. A missing restored run is recognized from the store's wrapped
   `no rows in result set`; identity mismatches and successful catalog absence
   also pop dead entries. Other failures preserve navigation and surface a
   retryable user-facing error.
10. Amendment 3 requires app-wide attention/history from the unpaged
    `WorkflowListItems` RPC. The pane releases it on close, but true paging while
    visible requires a new backend contract outside this packet. No terminal
    rows were silently dropped because that would break app-wide sweep.
11. Post-review confirmed `idx_usage_ledger_work_item` begins with
    `work_item_id`, while the mandated grouped query filters first by
    `project_id`. A `(project_id, work_item_id)` index would improve scale, but
    migrations are explicitly forbidden here; the exact P2 query was retained.
12. Unified file grouping uses the repository's canonical `parsePatchFiles`
    helper (the flat `utils/diff.ts` parser cannot produce per-file rows).
13. The deterministic studio UUID uses a fixed namespace plus
    `(projectId, workflowId)`; title is presentation-only, so rename and restart
    do not duplicate the singleton.
