## ASSUMPTIONS

- Notification tallies are process-local and may reset on restart, as explicitly permitted. They are keyed by project because a summary target requires one project id.
- A drain's final outcome for an auto-policy item is known only after auto disposition settles. Done is therefore tallied after the serialized auto worker finishes; a refusal is tallied once as `needs-human(disposition)`.
- Async digest upgrades are best-effort quality improvements. Two generator slots bound process/memory fan-out; saturation or generation failure logs the condition and retains the already-persisted deterministic template.
- A real transport-backed App has an event bus and notification sender configured before workflow attention events. Bare unit constructions intentionally keep only the deterministic digest rather than launching provider CLIs.
- “Per resolvable workflow” means configuration resolution/parsing must succeed. Resolved definitions that fail dry-run validation remain listed with their first finding; a configuration-level resolution error fails the RPC visibly.
- Predicted queue position uses the exact project-local next sort position and global scheduler ordering at read time. Existing equal-millisecond items are predicted ahead of the candidate because its future UUID tie-break does not exist yet.
- Disposition policy and merge base are read from the live project profile when disposition runs; a blank live base falls back to the persisted item base. Cleanup policy is frozen in the item snapshot.
- `cleanup: auto` applies after any successful merge/PR disposition, including a user-triggered disposition of a workflow whose frozen cleanup policy is auto. It never runs before the receipt is durable.
- “Discard” means the existing non-forced guarded worktree-removal path. It clears the item's workspace metadata but does not invent a separate forced branch-deletion path.
- PR `prRef` is the existing forge layer's returned PR/MR reference (normally its URL); `sha` is the full worktree HEAD read before the irreversible forge call.
- A failed cleanup after a landed, receipted disposition remains a visible `workflow:error`; it is not misrepresented as an unlanded refusal.
- Notification deep-link activation routing for the two new kinds remains intentionally deferred; this packet guarantees only validated opaque round-trip wire shape.
