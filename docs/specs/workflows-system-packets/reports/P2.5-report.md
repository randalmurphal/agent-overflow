release path. The worktree is intentionally left dirty and no mutating git
operation was used.

## ASSUMPTIONS

- “Exceeds” is strict: a measured value equal to its ceiling is allowed; a
  value greater than the ceiling parks the item.
- A persisted `work_items.budget` is the frozen item override. When it is
  absent, the live project profile's `reliability.per_item_budget` is read at
  each attempt boundary; when both are absent, spend is not queried.
- Resource waiting is part of item wall-clock time. The budget is therefore
  checked both before the attempt row is created and again immediately after
  resources are acquired, before the provider runner starts.
- `QueryWorkItemUsage.TotalTokens` follows the ledger's established billable
  token total: input + output + cache-read input + cache-creation input.
  Reasoning output is already included in provider output tokens where billed
  and remains separately reported by the ledger.
- The packet's frozen `SpendSource` returns one complete token/USD composition.
  If a `cost_source='none'` model has no rate, composition fails visibly rather
  than treating unknown USD as zero. Consequently, the item parks setup-failed
  even if its selected ceiling is tokens; silently returning a partial USD
  value would violate the specified USD ceiling.
- Claude emits no per-turn `EventTurnStart`. Its first `EventInit`, or a
  successful send when reusing an existing session, is the runner's turn-start
  signal. This is required for envelope-feedback and transient sub-attempts on
  the same session to have watchdog coverage.
- Provider read loops surface abnormal subprocess death as the ordered
  `session_status:error` then `session_status:disconnected` pair. The runner
  records the first event but starts backoff only after the App unregisters the
  session on the second event, preventing a short harness backoff from sending
  into a dead registered session.
- The provider package's already-surfaced `ProviderEvent.Meta` and `Raw` fields
  are the classification boundary available to this packet. Provider parsing
  was not changed because `internal/provider/**` is forbidden.
- Codex supplies a typed `EventTurnStart` for each retry turn. Until it arrives,
  a terminal from the preceding Codex turn is ignored; process-death status is
  still observed and routed through the post-unregister retry seam.
- The thread-to-item map is process-local and bounded by active phase attempts.
  Startup crash recovery parks orphan running items before sessions resume, so
  no post-crash live turn needs durable attribution.
- Attribution is removed at outcome/Stop exactly as the packet requires. Any
  later provider tail is intentionally ordinary unattributed usage.
- `Runner.Stop` and watchdog stop retain the merged P2.4 contract: interruption
  failure is logged visibly, local runner state is detached, and the requested
  outcome is delivered rather than changing Stop's v1 return contract.
- Automatic reconnect may run after an abnormal session is unregistered. A
  retry still uses the standard session-ensure/send path, so it safely reuses a
  successfully reconnected session or creates/resumes one itself.
- Generated bindings were produced with `wails3 generate bindings -clean=true
  -ts`; no generated file was edited manually.

## Transient-signal allowlist

The classifier is provider-scoped and closed. A signal not listed here, a
malformed signal, or the right JSON shape from the wrong provider is not
transient.

| Signal | Provider | Surfaced at the runner |
|---|---|---|
| Abnormal subprocess/session death before an envelope | Claude and Codex | `EventSessionStatus` content `error`, followed by `disconnected`; backoff begins through `sessionDisconnected` after App unregisters the session |
| Assistant rate-limit enum | Claude | `EventError.Meta.api_error_enum == "rate_limit"`; waits for the declared turn-complete when `expect_turn_complete` is true |
| HTTP 529 overload precursor followed by assistant server error | Claude | `EventAPIRetry.Meta.wire.error_status == 529`, then `EventError.Meta.api_error_enum == "server_error"` in the same sub-attempt |
| Connection reset precursor followed by assistant server error | Claude | `EventAPIRetry.Meta.wire.error.connection.code == "ECONNRESET"`, then `EventError.Meta.api_error_enum == "server_error"` in the same sub-attempt |
| Network terminal reason | Claude | `EventTurnComplete.Raw.terminal_reason == "network_error"` with no envelope |
| Server overloaded | Codex | `EventError.Meta.wire.error.codexErrorInfo == "serverOverloaded"` |
| Usage limit exceeded | Codex | `EventError.Meta.wire.error.codexErrorInfo == "usageLimitExceeded"` |
| HTTP connection failed | Codex | the sole tagged object in `codexErrorInfo` is `httpConnectionFailed` |
| Response-stream connection failed | Codex | the sole tagged object in `codexErrorInfo` is `responseStreamConnectionFailed` |
| Response stream disconnected | Codex | the sole tagged object in `codexErrorInfo` is `responseStreamDisconnected` |

Explicitly excluded examples include Claude `timeout`, a plain Claude
`server_error` without the typed 529/ECONNRESET precursor, Codex
`internalServerError`, unknown Codex variants, multi-key tagged objects, and
all malformed or cross-provider metadata.

## Watchdog timer lifecycle

- Resolve T once for the phase attempt: phase `watchdog` > project profile
  `reliability.watchdog` > the named package default `15m`.
- Arm one runner-owned timer when Codex emits `EventTurnStart`; for Claude, arm
  on `EventInit` or after a successful send to an already initialized session.
- Reset its deadline to `now + T` on every event observed while that phase turn
  is active. A callback from before a reset rechecks the deadline and rearms
  for the remaining duration instead of tripping.
- Disarm on any terminal, when transient backoff begins, and whenever the
  attempt detaches through outcome or Stop. No watchdog exists while waiting
  for engine resources or while a backoff timer is active.
- Backoff uses the same single timer slot with the project schedule (default
  30s, 2m, 5m). The schedule length is the retry cap. Stop removes ownership
  and stops the timer; a queued send rechecks ownership under the per-attempt
  send lock.
- On watchdog trip, detach the attempt, stop the provider turn through the
  existing interruption machinery, and deliver `OutcomeStalled`; the engine
  maps it through its sole teardown to `needs-human(stalled)`.

## Budget composition arithmetic

- Token spend is the attributed ledger sum of input + output + cache-read input
  + cache-creation input tokens for the work item.
- Wire USD is `SUM(cost_usd)` only for rows whose `cost_source='wire'`.
- Each `cost_source='none'` group is priced with `internal/usagecost.Price` and
  added once. Wire rows are never repriced.
- The exact composition test uses a `$0.50` wire row plus one million each of
  input, output, cache-read, and cache-creation tokens for `gpt-5.2-codex`:
  `$1.75 + $14.00 + $0.175 + $0.00 = $15.925` estimated, then
  `$0.50 + $15.925 = $16.425` total USD and `4,000,000` total tokens.
- Unknown estimated models and unexpected cost-source values return explicit
  errors; they are never silently counted as zero.
- Wall-clock budgets do not query spend. They use the engine clock minus the
  persisted item `StartedAt`, clamp negative elapsed time to zero, and include
  elapsed milliseconds in the emitted `workflow:error` payload.

## Post-task review

The required six-lens parallel review was run. Validated findings fixed before
the final gates were:

- rechecking a wall-clock budget after a long resource wait;
- scoping Claude and Codex metadata to the declared phase provider;
- waiting for session unregister before starting a process-death backoff;
- ignoring a stale Codex terminal between backoff expiry and the next typed
  turn start;
- rearming Claude watchdogs for same-session sub-attempt sends; and
- using explicit names for envelope retry versus transient retry state.

Suggestions that required provider-package changes, a new stop contract, a
durable attribution tombstone, or unrelated usage/pricing refactors were not
applied because the packet's forbidden zones and standing scope rules prohibit
those expansions.
