## Exact field contract

### `claude.Config`

```go
// OutputSchema is the inline JSON schema passed to --json-schema when
// the session process starts. It is sticky for every turn in the session.
OutputSchema string
```

### `provider.SendOptions`

```go
// OutputSchema is the per-turn structured-output schema. Codex sends it
// as outputSchema on every schemaed turn; Claude ignores it because its
// output schema is fixed on Config when the session process starts.
OutputSchema json.RawMessage
```

### `provider.ProviderEvent`

The packet calls this the provider `Event`; the existing normalized event type
in this repository is named `ProviderEvent`.

```go
// StructuredOutput carries the provider's structured payload on
// EventTurnComplete. Nil means the turn produced no usable payload.
StructuredOutput json.RawMessage `json:"structuredOutput,omitempty"`
```

## ASSUMPTIONS

- The packet's provider-agnostic `provider.Event` refers to the repository's existing `provider.ProviderEvent` type.
- A Codex turn is schemaed when `SendOptions.OutputSchema` contains bytes; nil or empty means omit `outputSchema` and take the free-form path.
- “JSON-parse” means JSON syntax parsing only. The provider preserves the final message bytes after `json.Valid`; schema/value/size validation remains exclusively engine-side.
- Only Codex `item/completed` with wire type `agentMessage` is a structured-payload source, exactly as D2a states; the existing `assistantMessage` compatibility alias remains transcript-only.
- Claude's output schema is supplied directly on `claude.Config`; it is not added to `provider.SessionOptions` because schema selection belongs to the later phase-runner packet.
- Codex emits a non-empty turn ID on the `turn/start` response or `turn/started` notification before agent-message completion, matching the binding wire verdict and existing lifecycle contract.
