## ASSUMPTIONS

1. A “human gate” is an explicit `human` route and counts once per phase even if several predicates reach human routes. A plain `park` route is a generic needs-human outcome, not an approval/reject human gate.
2. Catalog phase order and the frozen workflow phase list are the run chain for ordinals and the approve target.
3. `work_item_phases.started_at` plus the existing indexed tie-breaks identifies the latest persisted phase consistently with the existing attention query.
4. Summary SQL may inspect the frozen snapshot with SQLite JSON functions, but the snapshot must not be selected into Go or sent on the list wire.
5. Old queue events can omit the new fields; loaded running items and current/global concurrency are the compatibility fallback.
6. `createdAt` is the only available spawn/queue timestamp. Automation rows call it spawned only when `source === "automation"`; no cadence is invented when none is on the item DTO.
7. P4.0 intentionally exposes `checkPhaseIds`, not configured check commands, so failed evidence uses the phase ID as the check label and envelope `details`, `detail`, or `summary` as its detail.
8. The existing full-branch-diff binding is the only diff API. The frontend therefore receives the full patch transiently, retains only file summaries, and refetches/extracts one file when expanded.
9. `DesignPreviewPanel` is not a generic artifact preview: it depends on design-thread/workdir state. With no eligible preview or default-file-app binding, artifact rows use the existing host `OpenInEditor` file-opening boundary.
10. Declared named output values come from the latest terminal (`completed` or `failed`) phase envelope with envelope status `done`; artifact declarations stay represented by the durable artifact list and are omitted from named kv values.
11. `schema.multiline` is authoring/UI metadata, valid only for `type: string`, and does not alter runtime JSON-value validation.
12. Item 17’s existing ordering/timer behavior was conformant; changing it would have been out of scope.
13. Build binaries, frontend build output, Playwright result metadata, and dependency installation metadata produced by gates are gate artifacts, not source edits listed above.
