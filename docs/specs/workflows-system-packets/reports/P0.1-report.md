## ASSUMPTIONS

- The empty string is reserved as the internal global observer scope; real thread subscriptions require a non-empty thread ID.
- The packet requires synchronous callback delivery but does not define ordering among multiple matching observers, so no inter-observer order is promised. Global and thread callbacks receive the same provider event on the session read-loop goroutine.
- A callback registry change cannot affect the dispatch snapshot currently invoking it, but a concurrent session dispatch may observe that change immediately.
- The built-in global discussion observer intentionally lives for the App lifetime and therefore does not retain its unsubscribe function; all feature-created subscriptions own their returned unsubscribe function.
- Existing tests and internal helpers deliberately construct bare `App` values instead of calling `NewApp`; the once-guarded installation at session-handler construction is therefore necessary to preserve existing discussion behavior without modifying those tests.
- The first post-change `make test-race` failure was treated as non-reproducible only after the exact unmodified command passed on retry and the new observer tests also passed under focused race execution. Both attempts are recorded below.

## Dispatch ordering

`a.dispatchTurnObservers(threadID, evt)` is the only registry dispatch point. It is synchronous on the session read-loop goroutine and sits immediately after the `a.triage.Handle(evt)` block. Thus triage handling is always attempted before observers, and the discussion observer performs the same kind check, call, log, and exact `emitWireErrorToThread(...)` message on that goroutine.

The existing pre-triage branches remain in place: session activity recording, init/MCP ingest, and turn-start auto-reconnect clearing still run before triage. The existing post-triage branches also remain in place and now follow observer dispatch: dead-on-arrival reap, provider rate-limit probes, session-error queue restoration, disconnect unregister, and auto-reconnect. No branch besides discussion sync moved or changed. Ordering is preserved by synchronous dispatch: triage returns before the snapshot is invoked, every observer returns before later handler branches run, and callbacks are invoked outside the registry lock.
