## ASSUMPTIONS

- `DefinitionSource.Resolve` returns a dry-run-validated workflow. The engine
  freezes that result at run start and never re-resolves a non-empty snapshot.
- A new `Engine` instance is constructed for each app lifecycle. Engine
  instances are deliberately one-shot so closed command/done channels and
  recovered coordination state cannot be reused.
- The queue is globally ordered by `sort_position`, then `created_at`, then id;
  per-project reorder still supplies the store's required complete project set.
- A positive process-N bound counts item start attempts, including an item that
  immediately parks `setup-failed`; the bound is in memory only.
- Worktree/branch/base-branch fields are prepared by a later packet. P2.2
  freezes the values already present on the queued item without creating a
  workspace.
- Runner `done`, `question`, and `stuck` envelopes already passed P2.3
  post-validation. The engine caps seeds at 64 KiB and frozen snapshots at
  4 MiB; execution-failure/stopped outcomes may have no envelope.
- Optional envelope outputs represented by JSON `null` are absent from runtime
  variable lookup. `exists` is the only leaf operator that inspects absence;
  combinators consume ordinary Boolean child results.
- Project capacity values are environment facts read anew on every acquisition.
  A missing/non-positive capacity is `needs-human(setup-failed)`, not an
  indefinitely blocked semaphore.
- `cancelled` uses typed reason `interrupted` because the settled closed reason
  set has no separate `cancelled` reason. A gate route to terminal `failed`
  uses `check-failed-genuine`.
- Both authored `park:` and human routes initially use typed reason `gate`.
  Their persisted gate decision distinguishes generic `Resume` from
  `ResolveHumanGate`, preventing bounded human rejection from being bypassed.
- A human rejection note is capped at 16 KiB and is persisted in intervention
  JSON plus delivered through `RunRequest.Feedback` to the loop target.
- Parked and terminal items hold no in-memory scheduler entry. Resume loads a
  parked record and frozen snapshot from SQLite; acknowledged human decisions
  waiting for the global cap remain as small pending ids and retry on slot
  release.
- Engine timestamps are monotonically increasing millisecond values even when
  multiple transitions share the same wall-clock millisecond, keeping the
  existing phase ordering contract deterministic.
- An emitter is synchronous, prompt, and non-reentrant. Public error payloads
  are redacted; the non-JSON `ErrorEvent.Cause()` retains the diagnostic cause
  for local emitter handling.

## Implemented FSM transition table

| Current state | Trigger | Next state | Typed reason |
|---|---|---|---|
| queued | queue drain starts item | running | — |
| running | gate advance or bounded loop | running (next phase/attempt; no item-state write) | — |
| running | terminal success route | done | — |
| running | terminal failed route | failed | check-failed-genuine |
| running | human route or explicit park | needs-human | gate |
| running | question envelope | needs-human | question |
| running | stuck envelope | needs-human | stuck |
| running | execution failure / runner start failure | needs-human | agent-error |
| running | stopped outcome | needs-human | interrupted |
| running | loop/reject bound exhausted | needs-human | retries-exhausted |
| running | no-match, malformed routing, or corrupt snapshot | needs-human | wiring-error |
| running | missing workflow/live capacity/setup failure | needs-human | setup-failed |
| running | cancel command | cancelled | interrupted |
| running | startup finds non-terminal current attempt | needs-human | interrupted |
| needs-human | generic resume of non-human park/question/stuck/etc. | running | — |
| needs-human | persisted human approve/reject decision | running, then routed | — |
| done / failed / cancelled | any trigger | invalid | — |

All other state pairs are rejected. Any transition to `failed`, `needs-human`,
or `cancelled` rejects an empty or unknown typed reason.

## Teardown call sites

`(*Engine).teardown` in `fsm.go` is the sole teardown implementation and the
only caller of `releaseResources`. It is called from:

- `cancel` — active human cancellation.
- `parkUnstartable` — definition resolution, empty workflow, snapshot encoding,
  or snapshot-size setup failures.
- `enterPhase` — missing phase, variable/input encoding, phase-row creation,
  or live-profile/capacity setup failures.
- `startRunner` — runner start failure after acquisition.
- `startWaiting` — waiter wiring/profile/context/start failures.
- `complete` — done/question/stuck/execution-failure/stopped/unknown outcomes.
- `completeDone` — envelope/context, phase lookup, loop-trace, evaluator, and
  trace-encoding failures.
- `finishDecision` — every normal phase exit, terminal route, gate park,
  retry-exhaustion park, and no-match park.
- `rebuild` — corrupt-snapshot park, interrupted crash sweep, and inconsistent
  terminal recovery park.

Human decisions do not release independently: the phase was already fully
torn down before it entered `needs-human(gate)`. Resolving the persisted gate
only updates the parked phase's decision/intervention and resumes routing.
