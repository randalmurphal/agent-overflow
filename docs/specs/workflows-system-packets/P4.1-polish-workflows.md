## Work plan

Wire-backed (Go + bindings + frontend):

1. **Human-gate count in the catalog (§3.2/§7.1).**
   `WorkflowListDefinitions`'s per-definition DTO gains a human-gate
   count derived at parse/resolve time in `internal/workflow/def`
   (a gate with a route parking to needs-human). Workflow row line 2
   and the intake picker card meta render `5 phases · 1 human gate`
   (singular/plural; omit when 0).
2. **Phase progress on cold load (§4.2/§6.1).** Sidebar and run rows
   show `implement · 2/5` for running items without waiting for a
   live phase event this session. Source the current-phase ordinal +
   total server-side from `work_item_phases` + the item's phase list
   (a cheap indexed aggregate on the list paths — no N+1 per item; if
   that cannot be done cheaply, BLOCKED with your analysis, do not
   bolt on per-item queries). The existing sidebar unit test pinning
   "progress only after a phase event" is superseded by this item —
   amend it to pin the new behavior.
3. **Slots in queue state (§3.1).** The `workflow:queue-state` payload
   gains running-count and slot-capacity; the overview header renders
   the read-only dots + `n/m` with the spec tooltip. Engine emits the
   values it already owns; no new queries on the hot path.

Overview + workflow detail (frontend only):

4. **Overview controls as header chrome (§2.2/§3.1, F1.13).** Depth 0
   renders the queue toggle, slots, project filter, + New run,
   + New workflow, Triage as pane-header controls; depth > 0 renders
   back chevron (tooltip "Back (esc)") + clickable ancestor crumbs
   with `›` separators. Narrow widths collapse controls past the
   queue toggle into a `⋯` overflow menu (F1.10): container queries,
   end-first metadata truncation.
5. **Idle aggregate (§3.2, F1.5).** Idle workflow rows read
   `idle · last run 3d ago` (drop the fragment when the workflow has
   never run).
6. **Up-next row anatomy (§3.3, F1.7).** Rows render hover grip,
   `#position`, project dot, title, right meta
   `workflow · queued 3h` (`spawned 6m ago` for automation when the
   field exists; do not invent it) and `· held` while paused.
7. **Queued rank everywhere (§4.2/§5.3, F2.11).** Queued meta shows
   the item's 1-based rank within its project's queued set (sorted by
   sortPosition), never the raw `sortPosition + 1`.
8. **Backspace pops (§2.2/§9, F2.17=F1.9).** `Backspace` pops one
   level at any depth, no-op at overview, suppressed while a text
   field has focus — same guard path as Esc.

Run detail (frontend only):

9. **Header rows per spec (§5.1, F2.5 + F2.4).** Row 1: project chip ·
   state word · sweep counter `2 of 4` + progress dots (current
   highlighted, resolved green) + `j` `k` hints when in a sweep.
   Row 3 hint line: `workflow · phase 4/5 · parked 7h · $3.10`; done
   shows `finished 2h ago`.
10. **Approve names its target (§5.3, F2.6).** The gate approve button
    reads `Approve → <next-phase>` where next-phase is the phase after
    the parked one in the run's chain; plain `Approve` when it's the
    last phase.
11. **Gate leads with the diff (§5.3, F2.10).** Entering a gate-parked
    run auto-loads the diff file list (rows `path +a −d`); hunk
    expansion stays per-file on click. No eager hunk loading — the
    file list only (frontend memory stays bounded).
12. **Failed evidence block (§5.3, F2.9).** Failing check line
    `✗ <check> — <detail> ×N · genuine`, humanized reason word, latest
    diagnosis as an italic quote with attempt number
    (`diagnosis #3: "…"`).
13. **Auto-merge receipt kv rows (§5.3, F2.8).** Auto-policy merged
    receipts render the green header line plus kv rows: merge
    (`branch → base · mode · sha`), policy ("project opted in; a
    conflict or dirty base parks for you instead"), undo
    (`git revert <sha>`).
14. **Manual merge receipt suffix (§5.3, F2.7 remainder).** The
    session receipt appends `· worktree cleaned` on success; when the
    receipt carries `cleanupFailed`, omit the suffix (the
    workflow:error toast owns the failure).
15. **Queued-removal toast (§5.3, F2.12).** Removing an
    automation-sourced queued run notes it gets re-proposed next
    cycle; manual runs keep the current copy.
16. **All-clear summary labels (§5.4, F2.18).** The summary line reads
    `4 resolved — 1 approved · 1 answered · 1 handed off · 1 merged ·
    $11.54 reviewed` with per-kind labels (approved / answered /
    handed off / merged / re-enqueued / discarded), omitting
    zero-count kinds.
17. **Receipt-in-place ordering (§5.4, F1.14).** After acting inside a
    sweep, the receipt renders in place before the ~650ms
    auto-advance; stepping manually must never show the next run's
    content under the previous run's receipt. Verify against the
    current implementation and fix any mismatch; if it already
    conforms, say so in the report instead of changing code.
18. **Outputs block (§5.5, F2.15).** Declared named output values
    render as kv rows above the artifact rows. Artifact rows open by
    type: markdown/HTML through an existing in-app preview surface if
    one exists (find it and name it in the report — do NOT build a new
    preview component), everything else via the system opener.
