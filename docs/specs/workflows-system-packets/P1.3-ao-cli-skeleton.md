## Binding design decisions

- **Binary:** `cmd/ao/` (package main), installed as `ao`. Subcommand
  routing without new dependencies. `--help` at every level; errors to
  stderr; non-zero exit on failure. Keep main thin — logic lives in
  importable packages so M4 can grow without rewriting.
- **Config-root discovery:** reuse the same path logic the app uses (via
  `internal/settings` or the shared helper you find there). An explicit
  `--config-root` flag overrides discovery (this is what harness/e2e tests
  will use in M4 — make it first-class, not an afterthought).
- **`ao workflow validate [path | --id <id>]`:**
  - With a path: parse + validate that single definition file (resolver
    context = its directory).
  - With `--id`: resolve across the configured scopes (project scope needs
    `--project <slug>`; shared otherwise) and validate the winner.
  - Output: human-readable findings (one per line: element, code, message),
    plus `--json` for the typed result. Distinct exit codes: 0 valid,
    1 findings, 2 operational error (unreadable file, unknown id). The
    bindability status (checked/unchecked) must be visible in both output
    modes — if a profile for the project scope is loadable, use it;
    otherwise report unchecked, never silently pass.
- **`ao workflow list`:** resolved view over the scopes: id, name, scope
  (shared/project), source path, and whether a project definition shadows a
  shared one. `--project <slug>` adds that project's scope; `--json`
  variant. Zero workflows is a normal, quiet result (exit 0), not an error.
- **No RPC in this packet.** Do NOT implement the loopback client, token
  discovery, or any `ao run` plumbing — D15's token/RPC surface is M4 and
  will be designed against the transport package then. (If you believe some
  small interface belongs here to keep M4 clean, note it in the report;
  do not build it.)
- **Build wiring:** `make go-build` must compile the new binary (verify the
  Makefile's package discovery picks up `cmd/ao` automatically — read how
  GO_PACKAGE_ROOTS works; if it does not pick it up, that is a BLOCKED, not
  an invitation to edit the Makefile).
- Tests: table-driven CLI tests invoking the command funcs directly (not
  subprocesses) over `t.TempDir()` config trees: validate-valid,
  validate-with-findings (exit-code semantics), unknown id, list with
  shadowing, `--json` shape stability.
