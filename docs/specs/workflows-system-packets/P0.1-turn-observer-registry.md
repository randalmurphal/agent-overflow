## Intent

Introduce an App-level **turn observer registry**: a subscription API that
lets internal features observe provider events per-thread (or globally)
without adding bespoke branches to the session event handler in
`app_provider_events.go`. Migrate the one existing feature hook — the
discussion turn sync — onto it. Behavior must be identical afterward.

This registry is the seam the future workflow engine (M2) will consume; this
packet only builds the seam and proves it with the discussion migration. Do
not build any workflow-specific functionality.

## Design decisions (binding)

- New file `app_turn_observers.go` in the root package. Registry state lives
  on `*App`, guarded by its own mutex, following the style of existing
  App-level tracking maps.
- An observer subscribes for a specific thread ID, or globally (all threads).
  The callback receives every provider event for its scope — the registry is
  kind-agnostic; observers filter on `evt.Kind` themselves. Match the event
  type the session handler closure already uses.
- Registration returns an unsubscribe func. Unsubscribe must be idempotent
  and leak-free (entry fully removed; empty per-thread buckets cleaned up).
- **Exactly one dispatch point**, in the session event handler, immediately
  after `a.triage.Handle(evt)` — persistence-before-observers is the ordering
  invariant. Dispatch is synchronous on the same goroutine; no per-observer
  goroutines; no panic recovery (internal consumers only; failures must be
  loud per repo error philosophy).
- Snapshot the observer list under the lock, invoke callbacks outside it, so
  a callback can unsubscribe itself or register others without deadlocking.
- **Discussion migration:** replace the `EventTurnComplete` →
  `syncDiscussionTurn` branch with a global observer registered once at App
  construction/startup that performs the identical logic — same kind check,
  same call, same error handling including the exact
  `emitWireErrorToThread(...)` message. Behavior parity outranks elegance: do
  NOT convert discussions to per-thread registration in this packet.
- Every other branch in the closure (init MCP ingest, auto-reconnect clear,
  dead-on-arrival reap, rate-limit probes, session-status handling) stays
  exactly where it is.
- If `docs/architecture/invariants.md` enumerates long-lived maps and their
  cleanup paths, add the new registry map's entry there. That is the only
  permitted docs edit.
