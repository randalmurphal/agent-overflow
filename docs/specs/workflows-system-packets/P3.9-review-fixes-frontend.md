## Work plan

Stores:

1. **Pane authoritative refresh (S2+S3).** `applyWorkflowItemState`
   keeps the immediate state/reason patch AND schedules a coalesced
   authoritative reload of the pane's items (paneActive only), following
   the sidebar pattern; `loadWorkflowOverview` captures item events
   arriving during its fetch and re-applies them after assignment. Unit
   tests: an event during fetch survives the RPC assignment; a
   disposition recorded backend-side becomes visible without navigation.
2. **Level guard (S1).** `loadWorkflowCurrentLevel` re-reads the current
   level after each await and abandons stale work.
3. **Transport gap (S4).** `applyTransportGap`
   (`eventsTransportGap.ts`) gains a case for `workflow:item-state` /
   `workflow:phase-state` / `workflow:queue-state` →
   `refreshWorkflowsSidebar()` + reload the pane's current level when
   the pane is active. Unit test alongside the existing gap tests.
4. **Retarget keeps the filter (S6=F1.4).** `retargetWorkflowsPane`
   stops assigning `projectFilter`. `selectedProjectIds()` returns the
   union of the filter selection and any project referenced by the
   current stack so deep links outside the filter still render their
   workflow/run levels. Sweep membership keeps respecting the overview
   filter (§5.4). Tests: retarget outside the filter leaves it intact;
   the middle (workflow) level lists the target's runs.
5. **Sweep timer + index (S7, S8).** `stepWorkflowSweep` clears
   `autoAdvanceTimer` first (test: manual step after a receipt cancels
   the pending auto-advance). `getWorkflowSweep` clamps its fallback
   index to the current set's bounds.
6. **Restore truncation (S9).** `restoreWorkflowsPaneState` treats
   missing-target errors ('no rows in result set') at ANY level as
   truncate-to-parent; other errors keep the toast.
7. **Sidebar definitions for run-less projects (S5).**
   `loadWorkflowSidebar` fetches definitions for every known project
   (caller passes ids from `getProjects()`), not only run-bearing ones.
8. **Activation serialization (S10).** Post-hydration activations chain
   sequentially (same ordering the pre-hydration drain guarantees).
9. **Null seeds (S12).** `compactWorkflowSeeds` filters `null` too;
   extend its unit test.
10. **Intake self-loads definitions (C10).** The dialog fetches
    `WorkflowListDefinitions(projectId)` for its selected project
    itself and drops the `loadWorkflowOverview()` side effect in
    `initialize()`; switching project re-fetches. Test: pane filter on
    project A, dialog selecting project B lists B's workflows.

Components:

11. **Failed action row re-enqueues (R-A).** "Re-enqueue with guidance"
    (button and the `a` key on failed) dispatches
    `WorkflowReenqueueFailedItem` via a new `re-enqueue` action kind in
    `workflowActions.ts`; receipt message
    `Re-enqueued with the diagnosis as guidance — position N` where N is
    the run's rank in its project's queued set. A failed item with a
    persisted disposition receipt renders the receipt block and does NOT
    offer Re-enqueue (mirrors the backend refusal).
12. **Disposition-park action row (R-B).** `needs-human(disposition)`
    renders the done-manual actions (Merge to main / Create PR /
    Continue with agent / Discard) instead of the generic resume row,
    and the `a`/`r`/`t` keys route accordingly.
13. **Keyboard mirrors affordances (C4=F2.13).** `handleActionKey`
    short-circuits when a session receipt exists (Back/esc only); with a
    persisted disposition and no session receipt, only `t` stays live.
14. **Receipt + disposition co-render (C3).** The session receipt row
    renders above the persisted disposition block instead of replacing
    everything.
15. **Armed key includes state (C1).** The armed-confirmation key adds
    state+reason so a state change re-arms.
16. **Reject note autofocus (F2.14).** Mirror the answer input's focus
    path.
17. **Question source (F2.16).** The question quote and digit
    suggestions read the parked phase's output envelope question (the
    newest parked attempt in `detail.phases`), not the rewritable
    digest. Keep the digest as fallback when no envelope question
    exists.
18. **Merge receipt copy.** Use `receipt.base` and a mode label:
    `Merged to <base> — fast-forward <sha8>` (map `ff` → fast-forward,
    reusing the existing mode mapping); `cleanupFailed` stays a success
    (the workflow:error toast covers the cleanup).
19. **Neutral state casing (F2.3).** `workflowRunSignal` maps neutral
    states to Done/Queued/Running/Cancelled; update the two e2e
    assertions that pin lowercase (`workflows-run-actions.spec.ts`
    ~lines 98 and 179).
20. **Run rows say "Needs you" (F1.1)** in `WorkflowDetail`; reason
    words stay in the run-detail header.
21. **Human run-row meta (F1.2).** `WorkflowDetail.meta()` builds
    per-state fragments (reason word, parked/finished age, phase
    progress via the sidebar phase-progress helper where available,
    cost) instead of raw `state · reason` tokens. The `asks — <q>`
    fragment needs wire data that doesn't exist — leave it out and note
    it in the report.
22. **Done-awaiting-disposition is live (F1.3).** `WorkflowDetail`'s
    Runs list includes parked done runs (`isWorkflowParked`); History
    gets them only once disposed.
23. **Empty sweep entry → all-clear (F3.6).** A sweep-at-run entry
    whose sweep set is empty after load lands on the all-clear level.
24. **Queue drag feedback (C7/C8 partial).** Cross-project drags show
    an explanatory toast (order is per-project for now) instead of a
    silent no-op; add an after-last drop zone and a visible drop
    indicator during drag.
25. **In-flight guards (C9)** on the overview's queued-cancel and
    reorder actions.
26. **Remote artifact rows (C11=F4.7).** Disabled with title "Local
    only" when `isViewOnlySession()`.
27. **Copy (F2.19=F4.8).** "…thread opened in the run's worktree".
28. **Intake base branch editable (F3.2).** The base-branch input
    becomes editable, prefilled from `catalog.baseBranch`, passed
    through `WorkflowEnqueueItem`'s baseBranch parameter ('' when
    untouched/empty → profile default). Update the dialog unit test.

e2e (each new spec file follows the worker-fixture isolation rules):
