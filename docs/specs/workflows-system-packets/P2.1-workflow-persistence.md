## Intent

The persistence layer for the workflow engine (spec §10 "run record", decisions
D8): new SQLite tables via append-only migrations, plus bare store CRUD. No
engine logic, no scheduling, no bound methods — the engine (P2.2+) builds on
this API.

## Binding design decisions

- **Migrations are append-only.** Never renumber or edit an existing
  migration. Verify the current head version in `migrate.go` before picking
  numbers (v22+ expected; adjust to whatever head you find).
- **Two migrations:**
  - **New tables + usage attribution** (normal migration): `work_items`,
    `work_item_phases`, `work_item_effects`, `automations`,
    `automation_cursors`, and `ALTER TABLE usage_ledger ADD COLUMN
    work_item_id TEXT NOT NULL DEFAULT ''` with an index supporting the
    per-item budget sum.
  - **`threads.mode` gains `'workflow'`** (Rebuild migration): follow the
    existing rebuild precedent that added `'terminal'` (see the rebuild
    migrations in `migrate.go`; foreign-keys-off discipline is documented
    there).
- **Table shapes (D8, binding).** TEXT ids consistent with house style.
  Run-record tables carry **no FK to threads or projects** (records outlive
  both — usage_ledger precedent); denormalize the ids.
  - `work_items`: id PK, project_id, goal, workflow_id, workflow_scope
    CHECK(`project`|`shared`), snapshot JSON (empty until run-start freezes
    it), state CHECK(`queued`|`running`|`needs-human`|`done`|`failed`|
    `cancelled`), reason TEXT CHECK in the spec §2 typed set (`''` while
    running/queued; enforce non-empty via CHECK only if house style has
    precedent, else engine-enforced), sort_position INTEGER (drag reorder —
    queued-set resequencing is fine; no fractional ranks), seeds JSON, step
    mode INTEGER 0/1, worktree_path/branch/base_branch TEXT, budget JSON
    (`{"kind":"tokens"|"usd"|"wall_clock","limit":N}` or empty), source
    CHECK(`manual`|`agent`|`automation`) + source_ref TEXT, created_at/
    started_at/ended_at.
  - `work_item_phases`: one row per phase **attempt**. item_id, phase_id,
    attempt INTEGER, thread_id TEXT (denormalized, no FK), input_envelope
    JSON, output_envelope JSON, gate_trace JSON, intervention JSON,
    narrative_path TEXT, status CHECK(`running`|`completed`|`parked`|
    `failed`|`cancelled`|`superseded`), started_at/ended_at,
    UNIQUE(item_id, phase_id, attempt). Loop counters are **derived** from
    these rows — no separate counter table.
  - `work_item_effects`: item_id, phase_id, tool, payload_hash, payload JSON,
    created_at, UNIQUE(item_id, phase_id, tool, payload_hash) — the
    surface-and-skip ledger (spec §5).
  - `automations`: id PK, project_id, workflow_id + workflow_scope, name,
    enabled INTEGER 0/1, trigger JSON (cron | internal event), condition JSON,
    seeds JSON template, notes TEXT NOT NULL DEFAULT '' (D12 job notes),
    created_at/updated_at.
  - `automation_cursors`: automation_id, source_key, cursor TEXT, updated_at,
    PK(automation_id, source_key).
- **Retention rule (D8):** nothing in this packet may hook run-record tables
  into thread/project deletion paths. If an existing cleanup path would need
  edits to AVOID touching them, that's a BLOCKED, not an edit.
- **CRUD surface** (new files, e.g. `work_items.go`, `work_item_phases.go`,
  `automations.go` — keep each under ~500 lines): create/get/list work items
  (list filterable by project + states, ordered by sort_position then
  created_at), state transition update (state + reason + ended_at in one
  statement), snapshot/worktree/started_at update for run-start, queued-item
  reorder, phase-attempt create + complete (output envelope, gate trace,
  status, ended_at) + list-by-item + current-attempt lookup, intervention
  update, effect record + lookup, automations CRUD + enable toggle + notes
  get/set, cursor get/set, and the usage sum for a work_item_id (tokens +
  cost — mirror the existing usage_ledger query style).
  **Bare CRUD only**: no state-machine validation beyond CHECK constraints
  (the engine owns transitions), no goroutines, no events.
- Go types: exported structs with `json` tags per house style (see
  `store.Project`); JSON columns as `json.RawMessage` unless an existing
  store pattern says otherwise — match what the file you're next to does.
- Migration test per convention in `migrate_test.go` (fresh DB reaches head;
  new tables + CHECKs exercised; rebuilt threads table preserves rows and
  accepts `mode='workflow'`), CRUD tests alongside each new file.
- Update `docs/architecture/schema.md` and `internal/store/AGENTS.md`
  in-change.
