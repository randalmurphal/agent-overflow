## Intent

Make the workflow system harness-testable end to end and prove it with
deterministic e2e specs: `HarnessSeed` learns to seed workflow definitions,
profiles, and work items (through production paths only), the mock provider
learns to actually abort an in-flight scenario turn on interrupt, and the
Playwright suite gains zero-sleep workflow specs covering the drain, a human
gate park/approve, a question answer, a watchdog stall, and cancel.

Out of scope: any frontend/UI change (M3 — these specs assert via RPCs and
events, not workflow UI), new engine/runner behavior (if a needed behavior
is missing, that is a BLOCKED with evidence, not a feature add), record/
replay bundle format changes.

## Binding design decisions

### HarnessSeed `workflows:` (obligation b)

- `HarnessSeedProject` gains a `workflows` section with two parts:
  - **Definitions + profile**: named workflow definitions (YAML + prompt
    files, written into the harness config dir at the exact locations the
    app's DefinitionSource/ProfileSource read — D1/D6 layout, reusing the
    same path helpers, never a parallel layout) and an optional project
    profile (which is where harness runs shrink watchdog/backoff values to
    milliseconds).
  - **Items**: `items: [{workflow, goal, seeds, stepMode, count, target}]`
    where `target` is a desired resting state (`queued`, or a state a mock
    scenario can deterministically produce — e.g. `needs-human` via a
    question/gate scenario, `done` via a completing scenario).
- **Production paths only.** Items are created via the same code path as
  `WorkflowEnqueueItem` and reach non-queued targets by actually running
  through the engine against mock scenario turns — never by writing
  work_item/phase rows directly. If a target state cannot be reached
  through production paths deterministically, that is a seed-spec
  validation error naming the target, not a side-door write.
- Seeding runs with the queue in a known state and restores the caller's
  queue configuration afterward; `HarnessReset` must return workflow state
  (items, phases, config-dir definitions, artifact/narrative dirs) to a
  blank slate.

### Mock interrupt abort (obligation c)

- Today both adapters ack interrupt but the engine finishes the scenario
  turn anyway. Fix in the ENGINE (once, both adapters benefit): an
  interrupt aborts the in-flight scenario turn at the next step boundary,
  skips remaining steps, and emits each protocol's genuine terminal frames
  for an interrupted turn (verify the real wire shapes against
  `docs/references/claude.md` / `codex.md` and the existing parsers — the
  app's triage must classify the aborted turn exactly like a real
  interrupt; spike policy applies if unsure).
- A `waitSignal`-blocked turn must also be interruptible (interrupt wins
  over waiting for advance; the pending gate is discarded).
- Cover both adapters with `cmd/ao-mockprovider` binary tests mirroring the
  existing test style.

### Deterministic workflow e2e (obligation d)

New Playwright specs following `e2e/tests/harness.spec.ts` conventions
(zero sleeps; await `harness:mock`, `workflow:*`, and turn events; all
backend setup through RPCs). Minimum set:

1. **Drain end-to-end**: seed a two-phase workflow + completing scenarios →
   enqueue via RPC → await `workflow:item-state` to `done`; assert phase
   rows via `WorkflowGetItem` (envelopes present, gate traces recorded).
2. **Human gate**: scenario parks at a human-routed gate → assert
   `needs-human(gate)` event → `WorkflowResolveGate` approve → runs to
   done. Use `waitSignal` + `HarnessMockCommand({type:"advance"})` so the
   park moment is deterministic.
3. **Question answer**: scenario ends a turn with a `question` envelope →
   assert `needs-human(question)` → `WorkflowAnswerQuestion` → the answer
   turn runs on the SAME mock session (assert via the mock's
   session-scoped events) → done.
4. **Watchdog stall**: seed a profile with a millisecond watchdog + a
   `stall` scenario → assert the item parks `needs-human(stalled)` without
   any test-side sleep (await the state event).
5. **Cancel**: a running turn (held open by `waitSignal`) →
   `WorkflowCancelItem` → assert `cancelled` state and that the mock saw
   the interrupt (harness control/event surface), exercising the new
   interrupt abort.

### Surface conventions

- New harness RPCs (if any are needed) stay on the Harness receiver — that
  inherits the registration gate and LocalOnly marking. Prefer reusing the
  existing `Workflow*` bound methods for anything a production client could
  do; harness-only RPCs are for seeding/inspection the product surface
  doesn't have.
- `make e2e` stays green as a whole — existing specs must not be disturbed.

## Invariants

- Seeding never writes work_item/phase rows directly — production paths or
  a named validation error.
- One config-dir layout: seed writers reuse the app's own path resolution.
- e2e specs contain zero sleeps/polling loops; every wait is an awaited
  event or RPC response.
- The mock's interrupted-turn wire output matches the real providers'
  interrupt shapes (parser-verified, not invented).
- Reliability values in harness profiles come from the profile fields P2.5
  added — no test-only override knobs in engine/runner code.
- Errors are user-facing state, not log entries.
