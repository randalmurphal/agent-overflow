## Work plan

Backend:

1. **usage_ledger partial index.** New migration:
   `CREATE INDEX idx_usage_ledger_project_work_item ON
   usage_ledger(project_id, work_item_id) WHERE work_item_id <> ''`.
   Add an EXPLAIN QUERY PLAN test (existing store-test helper pattern)
   asserting `WorkflowListItemCosts`'s query uses it.
2. **Server-side unresolved predicate (S11 slice).**
   `store.ListWorkItems` gains an option to return only "unresolved"
   items: state IN (queued, running, needs-human) OR (state IN (done,
   failed) AND disposition = ''). Ruling encoded here: **a
   disposition-bearing item is resolved regardless of state** — a
   discarded failed run must stop appearing in the sidebar/sweep.
   `WorkflowListItems` keeps its current signature; add a bound
   `WorkflowListUnresolvedItems(projectId)` (projectId '' = app-wide)
   using the predicate, backed by an indexed query — verify the
   existing state/project indexes serve it; if not, extend the item-1
   migration. Frontend `isWorkflowSidebarRun` must apply the same
   disposition rule so the two predicates agree (extend its unit test
   with a disposition-bearing failed row).
3. **StateEvent carries projectId; hooks stop overhydrating.**
   `engine` item `StateEvent` gains `ProjectID`. The app-side
   pre/post hooks (`app_workflow.go`, `app_workflow_digest.go`,
   `app_workflow_notifications.go`) skip full `GetWorkItem` loads for
   transitions that only need IDs (queued→running, running→done
   pre-work) and use a narrow read for attention digests where the
   full row (snapshot included) isn't needed. The wire event payload
   gains `projectId` (frontend consumes it in item 6).
4. **WorkflowItemDetailView DTO (B2).** `WorkflowGetItem` returns a
   deliberate view instead of raw rows: item fields WITHOUT the
   definition snapshot, plus explicit `checkPhaseIds` (computed
   server-side from the snapshot — this is the only thing the UI
   derives from it today: verify by finding every frontend consumer of
   `item.snapshot` and `checkPhaseIds` before you start; list them in
   the report); phase rows WITHOUT input envelopes, gate traces,
   interventions, and narrative paths (output envelopes STAY — the
   question flow reads them); artifacts + usage unchanged. Regenerate
   bindings (`-ts`), update frontend types + consumers. If any
   frontend consumer needs a dropped field, that is a BLOCKED
   condition, not a reason to keep the field.
5. **Waiting-set scheduler.** `startWaiting` stops scanning `e.items`:
   maintain an ordered waiting collection + membership map updated
   where the `waiting` flag changes. Queue ordering stays the waiter
   priority. Existing engine tests must pass unchanged; add one test
   that a waiter is picked up on release without a full-map rescan
   being observable (behavioral: release with many non-waiting items
   still starts the waiter).
6. **Phase-context narrow reads.** `variableContext`, `loopCounts`,
   and `nextAttempt` stop materializing full phase rows (input
   envelopes included) on every call: add a store read returning only
   the columns they consume (phase id, attempt, status, output
   envelope). No runtime cache — SQLite stays authoritative.
7. **Single-pass rebuild.** `rebuild.go` loads the global active set
   once and partitions by project-ID set instead of per-project lists
   + a second global list. Behavior (including the P3.8 orphan sweep)
   is pinned by existing tests; keep them green unchanged.
8. **Store test template DB.** `newTestStore` clones a once-migrated
   file-backed template (built in `TestMain`, WAL-checkpointed,
   closed) into `t.TempDir()` instead of running all migrations per
   test. Keep genuinely migration-testing tests on blank DBs
   (`migrate_test.go` step-through/idempotency, one explicit
   fresh-chain test). Measure `go test -race -count=1
   ./internal/store/` wall-clock before and after and put both numbers
   in the report; if the saving is not material (< 25%), revert the
   helper change and say so.

Frontend:

9. **Scoped refresh waves.** On `workflow:item-state`-triggered
   refreshes (sidebar AND pane): do NOT reload definitions — an
   item-state transition cannot change a catalog. Definitions still
   load on initialization, pane activation/retarget, transport gap,
   and intake open. Sidebar item refetch switches to
   `WorkflowListUnresolvedItems('')` (item 2). Pane overview refresh
   uses the event's `projectId` (item 3) to reload items+costs for the
   affected project only, merging into existing state; full multi-
   project reload stays for activation/retarget/gap. Report the
   before/after RPC count for one item-state wave with P projects
   known and K selected (the review measured 1+P+3K; target 1+2 — one
   sidebar list + one project items+costs).
10. **Adopt the detail view.** Frontend types/stores/components read
    `checkPhaseIds` from the DTO instead of parsing `item.snapshot`;
    remove the now-dead snapshot parsing helpers if nothing else uses
    them.

e2e: no new specs required; every existing spec must keep passing
unchanged (the harness exercises the changed wire methods end-to-end).
If an existing e2e assertion pins a payload shape items 3/4 change,
amend exactly that assertion and list it in the report.
