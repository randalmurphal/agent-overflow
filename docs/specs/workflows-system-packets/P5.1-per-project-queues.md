## House decisions (binding)

1. **Per-project queue state persists on the project row.** Migration
   v29 adds `workflow_queue_paused INTEGER NOT NULL DEFAULT 0` and
   `workflow_concurrency INTEGER NOT NULL DEFAULT 0` to `projects`
   (plain ALTER TABLE ADD COLUMN — follow the v12 channel-max-turns
   exemplar, not a rebuild). `0` concurrency means "no per-project
   cap"; valid range 0..32. Defaults preserve today's behavior exactly.
2. **Global controls remain the master.** `workflowQueueActive` off
   pauses everything; global `workflowConcurrency` is the total slot
   pool. A project's effective cap is `min(projectCap or ∞,
   globalConcurrency)`. Per-project pause only adds a gate; it never
   overrides a global pause.
3. **Engine owns per-project gating inside the command loop.** Seed
   per-project queue state when the app boots the engine, mutate it
   only through a new command mirroring the `UpdateQueueSettings` /
   `...DetachedStarts` shape (e.g.
   `UpdateProjectQueueSettings(projectID string, paused *bool,
   concurrency int)`). The drain must skip items whose project is
   paused or at its per-project cap WITHOUT disturbing the relative
   order of the remaining queue (a skipped item stays queued in place;
   do not rotate or re-sort). Track per-project running counts through
   the same start/teardown points that maintain `activeSlots` — no new
   release paths (engine invariant: `teardown` is the only release
   path).
4. **`QueueStateEvent` is extended, never renamed.** Add a
   per-project slice (project id, paused, concurrency, runningCount).
   Existing fields keep their names and meaning; the frontend's
   settings-fallback merge in `getWorkflowQueueState()` keeps working
   for consumers that ignore the new field.
5. **Queue UI becomes a list of per-project queues.** Inside the
   existing queue section of the workflows column: one group per
   project that has queued or running items, ordered by project name;
   group header shows project color dot + name, `running/cap` (cap =
   effective cap; render `∞`-style absence as just the running count —
   pick something consistent with UI-SPEC §5 row grammar and state it
   in the report), a pause/resume control, and a compact concurrency
   control. Rows inside a group keep the existing row grammar and
   drag-reorder (already per-project). A paused project's rows render
   the existing `held` treatment. No cross-project drag.
6. **Drain summaries flush per project.** Replace the global idle
   gates with per-project ones: flush a project's tally when THAT
   project has no running items and no startable queued items (queued
   items count as pending work only if both the global queue and the
   project are unpaused). Add the narrow store counter you need
   (project-scoped `CountWorkItemsInStates` sibling); do not widen the
   existing global one.
7. **`workflow:definitions-changed`.** A debounced (~250ms) fsnotify
   watcher over the workflow config root (shared + per-project
   definition directories — derive the exact layout from
   `internal/aocli`; watch directories, not individual files, and
   handle create/rename of new project dirs) emits
   `workflow:definitions-changed` (no payload needed unless you find
   per-project scoping trivial — if so `{projectId}` per event is
   fine). Frontend: when the workflows pane is active, a
   definitions-changed event refreshes the definitions catalog (and
   the intake dialog's list if open) through the existing load paths —
   no new polling. Watcher setup failure must be loud (logged error;
   app still boots) and the watcher must shut down cleanly with the
   app. Lifecycle lives in an `app_*.go` file, not inside the engine.
8. **Naming stays boring and consistent**: `workflow_queue_paused` /
   `WorkflowQueuePaused` / `workflowQueuePaused` across the layers;
   the bound method is `WorkflowUpdateProjectQueue(projectID string,
   paused *bool, concurrency *int)` (nil = leave unchanged), persisted
   first, then pushed to the engine, then reflected in the next
   `workflow:queue-state` emission.
