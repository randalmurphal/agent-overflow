## Intent

The three remaining §12 triggers — inactivity watchdog, transient-execution
retry, per-item budget — plus the usage attribution that budgets depend on.
All three PRESS the existing engine teardown; none of them adds a second
release path. Every timing/ceiling value is profile/config-driven so harness
profiles can shrink them to milliseconds (a hardcoded 15m in the trip path is
a spec violation, not a shortcut).

Crash recovery and cancel already exist (P2.2/P2.4). Worktrees, setup hooks,
derived read-only, step mode (P2.6), harness `workflows:` seeding and the
mock interrupt gap (P2.7), and all UI are out of scope.

## Binding design decisions

### One teardown, three buttons

No new engine release/teardown paths. The watchdog and retry exhaustion
deliver runner Outcomes; budget trips inside the engine call the existing
teardown. If you find yourself writing a second lock-release or a second
park sequence, stop — that is the exact failure §12 exists to prevent.

### Watchdog (park `needs-human(stalled)`)

- **Runner-owned timers; engine stays timer-free** (its AGENTS.md boundary
  stands). The runner arms one inactivity timer per active phase attempt
  when the turn starts; ANY provider event for that phase's thread resets it
  (the P0.1 observer registry already delivers every event — reset from the
  observer the runner already has).
- T resolution: per-phase override > profile `reliability.watchdog` >
  package default constant of 15m.
- Per-phase override: `def.Phase` gains an optional `watchdog:` YAML field
  (Go duration string, validated in def's validation with a named finding;
  authoring schema updated to match — keep def free of a profile import).
- On trip: the runner stops the in-flight turn via its existing stop
  machinery and delivers `Outcome{Kind: OutcomeStalled}` (new kind). The
  engine maps it through teardown to `needs-human` with the existing
  `ReasonStalled`. Additive: a new OutcomeKind case, no FSM rework.
- The timer is not armed while the phase waits on resources (the runner
  hasn't started — automatic) and is disarmed during retry backoff waits.

### Transient-execution retry (park `needs-human(retries-exhausted)`)

- **Runner-internal, sub-attempt.** The engine sees one phase attempt; the
  runner retries the TURN inside it. Retries re-run on the same thread
  through the standard session-ensure path (which resumes provider context),
  schema attached as always.
- **Conservative allowlist — frozen:** (a) session/subprocess death before
  any envelope arrived for the turn; (b) wire-typed provider overload /
  rate-limit signals; (c) connection/network error classes. Enumerate the
  concrete signals from the provider packages and list every one in your
  report. Anything ambiguous is NOT transient and parks immediately via the
  existing execution-failure path.
- Backoff schedule: profile `ReliabilityDefaults` gains
  `Backoff []Duration` (`yaml:"backoff"`); default 30s → 2m → 5m; the cap IS
  the schedule length. Harness profiles shrink it to milliseconds — no
  hardcoded sleeps in the trip path, and the wait must be abortable by
  `Runner.Stop` (cancel during backoff stops cleanly, no timer leak).
- Exhaustion delivers `Outcome{Kind: OutcomeTransientExhausted}` (new kind)
  → teardown → `needs-human` with the existing `ReasonRetriesExhausted`.
- **Distinct from D2a's envelope-invalid path** (one feedback retry turn →
  `agent-error`). That path is UNCHANGED; a turn that completes with an
  invalid envelope is never backoff-retried.

### Per-item budget (park `needs-human(budget-exhausted)`)

- Effective budget: `work_items.budget` (same JSON shape as
  `profile.Budget`; exactly one of tokens / usd / wall_clock) if set, else
  profile `reliability.per_item_budget`, else no ceiling.
- **Checked engine-side, before starting each phase attempt** (initial,
  loop-backs, resumes, answers) — never mid-turn. On exceed: teardown →
  `needs-human(budget-exhausted)`, spend-so-far in the emitted error event
  payload.
- New engine seam (additive, wired app-side like the P2.2 seams):
  `SpendSource { ItemSpend(ctx, itemID string) (Spend, error) }` with
  `Spend{Tokens int64; USD float64}`. The app implementation composes
  `store.QueryWorkItemUsage` (tokens + wire-reported USD) PLUS
  `internal/usagecost` estimates for rows whose `cost_source='none'` (Codex
  reports no wire cost — a USD budget summed from wire cost alone is a hole,
  not a ceiling; this composition is the carried P2.1 review finding).
  Wall-clock is computed engine-side from the item's `StartedAt` against the
  engine clock seam.
- `WorkflowEnqueueItem` gains an optional budget parameter (validated
  against the exactly-one-field rule; bindings regenerated).

### Usage attribution (budget's prerequisite)

- Usage rows for workflow phase-thread turns must persist `work_item_id`.
  The runner maintains an app-level thread→item registration (created with
  the phase thread, removed at outcome/Stop); the usage-persist path
  consults it and stamps the column. Non-workflow threads keep writing `''`.
  Post-crash there are no live turns for unregistered threads (the sweep
  parked them), so the in-memory map is sufficient — document that reasoning
  where the map lives.

## Invariants

- Every stop path runs the one engine teardown; zero new release paths.
- No hardcoded timing/ceiling values in trip paths — profile-driven with
  named package defaults only.
- The transient allowlist is closed and conservative; ambiguous → park.
- Envelope-invalid handling (one feedback retry → agent-error) unchanged.
- Watchdog measures stream inactivity, never wall-clock turn duration.
- Budget is the single runaway ceiling — do not add per-phase turn caps.
- Engine gains no timers, no goroutines, no FSM rework — outcome mappings,
  the budget check, and the SpendSource seam only.
- Errors are user-facing state, not log entries.
