## Binding design decisions

- **Schema in:**
  - `claude.Config` gains an output-schema field (inline JSON string).
    `buildArgs` renders it as `--json-schema '<inline JSON>'` — the inline
    schema text, NOT a file path. Session-sticky: passed once at spawn,
    applies to every turn of that session process (D2a#4). It must coexist
    with the full existing flag set (extend the options tests' pattern).
  - `provider.SendOptions` gains a per-turn output-schema field
    (`json.RawMessage`). **Codex**: rendered as `outputSchema` (camelCase)
    in `turn/start` params and **re-sent on every schemaed turn** — it is
    NOT sticky (D2a#4); a turn whose SendOptions carries no schema sends no
    `outputSchema` (that is the free-form/takeover path, D2a#5). **Claude**:
    `Send` ignores the per-turn field (schema is fixed at spawn); this
    asymmetry is deliberate — document it on the field.
- **Payload out:** the `EventTurnComplete` `provider.Event` gains an explicit
  structured-output field (`json.RawMessage`; nil when the turn produced
  none). Provider-agnostic consumers must never need provider branching.
  - **Claude**: payload lives at `structured_output` on the result event of
    the logical turn (D2a#4). A result with the field absent yields nil —
    **absence is a normal, non-error outcome** (D2a#3); do not synthesize an
    error. The existing `error_max_structured_output_retries` subtype
    handling stays exactly as is.
  - **Codex**: payload is the JSON-parse of the **final** `item/completed`
    agentMessage `item.text` of the turn — NOT anything on `turn/completed`
    (D2a#4). Only attempt the parse when the turn was schemaed (track the
    pending turn's schema state on the session); a schemaed turn whose final
    agentMessage fails to parse as JSON yields nil payload (engine-side
    post-validation owns all judgment — D2a#3). Unschemaed turns never
    populate the field.
- **No validation here.** The provider layer transports bytes. Schema
  validation, size caps, and status semantics are engine concerns (D2/D2a:
  engine post-validation is the sole success authority).
- Tests follow each package's existing conventions (arg-construction tests
  for claude flags; fixture-driven protocol tests for codex parsing):
  schemaed + unschemaed turns, payload present/absent/unparseable, flag
  coexistence, codex per-turn re-send and free-form omission.
- Update `internal/provider/claude/AGENTS.md` + `internal/provider/codex/
  AGENTS.md` if they document Config/Send surfaces (check; keep in-change).
