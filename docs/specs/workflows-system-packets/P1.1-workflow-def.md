## Intent

Create `internal/workflow/def`: the pure, engine-free foundation of the
workflows system. It owns the workflow **definition format** (YAML types +
parser), the **source resolver**, the **published JSON Schema** (embedded
authoring aid), the **envelope schema generator**, the **interpolator**, and
the **full dry-run validator**. No engine, no store, no transport, no CLI —
those are later packets that consume this one.

## Binding design decisions

- **Package:** `internal/workflow/def`, package name `def`. Pure functions +
  plain structs; no goroutines, no globals, no I/O beyond reading the
  definition/prompt files it is pointed at.
- **Parser:** `gopkg.in/yaml.v3`. Strict decoding — unknown fields are
  errors (`KnownFields(true)`), so typos fail loudly.
- **Resolver:** ordered list of `(dir, scope)` sources per D1; project scope
  wins on `id` collision; `id` is the declared field (validated `[a-z0-9-]+`,
  unique per scope), never the filename stem. Prompt files are sibling
  relative paths resolved against the definition's own directory; existence
  checked at validation time.
- **Published JSON Schema:** one embedded (`go:embed`) JSON Schema document
  describing the authoring format, exposed via an accessor. Writing it to
  disk next to workflow dirs is app wiring — OUT of scope here. Keep the
  schema in lockstep with the Go types; add a test that round-trips at least
  one valid fixture against both (parse succeeds AND fixture validates
  against the published schema) so drift fails a test. If full JSON-Schema
  validation needs a library we don't have, do structural spot-checks in the
  test instead — do NOT add a dependency.
- **Envelope generator** (D2a-1, BINDING): given a phase's declared outputs,
  produce a deterministic (stable key order) JSON Schema: flat top-level
  object, `additionalProperties: false`, EVERY property listed in
  `required`, branch fields typed `["T","null"]`, `status` enum
  `done|question|stuck`, declared outputs nested under `outputs` (itself
  `["object","null"]`; inside it, every declared output present in
  `required`, optional outputs nullable). Conditional semantics
  (question non-null iff status=question, etc.) are ENGINE post-validation —
  the generator must not attempt `oneOf`/`if-then` (both providers reject
  them, D2a).
- **Post-validation helper lives here too:** a pure
  `ValidateEnvelope(phase, payloadBytes)` that enforces the full semantics
  the schema can't express (status/branch-field conditionals, required
  outputs on `done`, size cap as a parameter — default 64KB, caller-supplied
  override) and returns typed, feedback-ready errors (the engine forwards
  them verbatim to the retry turn per D2 failure mode 2). No provider code,
  no engine code — just bytes in, verdict out.
- **Interpolator:** `{{var}}` / `{{var.field}}` only; single-pass; inserted
  values are inert (never re-scanned); absent optional renders the literal
  `(not provided)`; anything else that looks like a template but doesn't
  parse to a declared reference is a validation error at dry-run time, not a
  runtime surprise.
- **Dry-run validator:** validates a RESOLVED workflow (post-resolver) and
  returns ALL errors, not first-fail — each error names the offending
  element (workflow id, phase id, route index, variable name, file). The
  check list (union of spec §3–§5 rules and D2/D5):
  1. id format/uniqueness (per scope, in the resolver).
  2. Phase ids + workflow input names share one namespace; collisions
     rejected (D2-6).
  3. Every input reference resolves (bare name → workflow input;
     `phase.field` → upstream output).
  4. Producer-dominance: a required phase input must trace to a required
     producer whose phase dominates this phase in the graph; optional
     producers force the consumer to be optional; dotted-path refs into
     optional objects are optional themselves (D2-4/5, D5).
  5. Gate route targets exist; `done`/`failed` reserved terminals; first
     phase in the list is the start node; every phase reachable from start.
  6. Loop routes: target is a strict ancestor, `max >= 1` present.
  7. Predicates: only `eq neq gt gte lt lte in exists` + `all any not`;
     type-mismatched comparisons rejected against the declared output/input
     schemas; predicate references obey the same producer rules.
  8. Prompt file references exist.
  9. Bindability (D6): every check/resource-capacity/command binding a
     workflow names must be bindable. Validate through a narrow interface
     YOU define in `def` (e.g. `Bindings` with has-check/has-capacity/
     has-command lookups). A nil/absent binding source SKIPS these checks
     and the result must say so explicitly (distinct "unchecked" outcome,
     not silent pass) — `ao workflow validate` without a profile relies on
     this. The profile loader (P1.2) implements the interface later.
  10. Whatever workspace/read-only derivation spec §9 assigns to the
      definition layer (derived read-only runs) — implement the derivation
      as a pure function here so the engine and UI ask `def`, not recompute.
- Every rule above gets at least one table-driven golden test naming the
  offending element in the expected error. Valid + invalid fixture files
  live under `testdata/`.
- If you meet a spec construct whose semantics are genuinely engine-side,
  implement parse + structural validation for it and record the deferred
  semantic in the report's ASSUMPTIONS — that is not a BLOCKED. A construct
  that CONTRADICTS these binding decisions IS a BLOCKED.
- House error style: wrapped `fmt.Errorf` with `%w` for I/O; typed
  error/result structs for validation findings (they become CLI and UI
  surfaces later). No log-and-swallow anywhere (repo rule).
- Keep files under ~500 lines — split by responsibility (types / parse /
  resolve / validate_graph / validate_vars / envelope / interpolate), not by
  visibility.
