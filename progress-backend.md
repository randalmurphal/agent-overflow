# Backend Loop — Progress Tracker

## Status: IN PROGRESS

## Codebase Patterns

- `internal/store/migrate.go` owns schema setup through ordered `Migration` entries plus small helper functions; legacy pre-version databases are backfilled into `migration_versions` before newer migrations run.
- `internal/git/core.go` centralizes bounded command execution while `internal/git/status.go` keeps git porcelain parsing and repository queries separate from process management.
- `internal/discussion/registry.go` owns discussion-definition validation and persistence rules, while `internal/discussion/channel.go` and `internal/discussion/deliberation.go` keep channel lifecycle and turn-state logic split into separate services.

- 2026-04-15: Review sweep fixed legacy migration backfill drift for pre-version parity databases: startup previously recognized only unversioned v1 schemas, so any older local database that already had the parity-era v2 thread columns and tables but no `migration_versions` rows would try to reapply `ALTER TABLE` statements and fail on duplicate columns. The migration runner now detects both unversioned v1 and unversioned v2 schemas, backfills the appropriate migration history before applying newer migrations, and preserves existing thread data during startup.
- 2026-04-15: Integration-wiring sweep fixed a design-mode parity gap for Claude threads: design-mode sessions were loading the design system prompt, but `render_design` / `present_options` tool-use blocks emitted by Claude were never routed into the backend design reactor, so artifacts/options were not actually materialized. Claude design tool-use events now dispatch through the reactor, rendered artifacts persist correctly, and completed option selections flow back through the normal send path as a follow-up user choice message.
- 2026-04-15: Spec-compliance sweep fixed settings/provider-status drift for blank binary paths: the settings service now normalizes empty `claudeBinaryPath` / `codexBinaryPath` values back to the default executables (`claude`, `codex`) on both load and update, preserving Forge parity and keeping provider-status probes consistent with the actual session launch path.
- 2026-04-15: Review sweep fixed settings-system parity drift: the JSON settings service now rejects invalid enum and blank default-model updates, sanitizes invalid on-disk values back to spec defaults while preserving valid fields, normalizes `recentWorkspaces`, and `App.CreateThread` now records user workspaces into the recent-workspace list so the backend actually wires the settings feature it already exposed.
- 2026-04-15: Review sweep fixed git/thread metadata drift: `CreateThread` now initializes `ProjectPath` from the git root when available (falling back to the workspace path), and worktree bindings now keep thread `WorkspacePath`/`WorktreePath`/`Branch` metadata in sync on create/remove so repo-level and worktree-level backend bindings operate on consistent thread state.
