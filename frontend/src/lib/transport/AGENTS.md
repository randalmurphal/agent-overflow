# Frontend transport

This directory is the client half of the shared HTTP and WebSocket transport for
the embedded webview, `agent-overflow --connect`, remote browsers, and the native
shell. Server protocol and authorization rules live in
[internal/transport/AGENTS.md](../../../../internal/transport/AGENTS.md). The
wire walkthrough, replay model, credentials, and failure classification live in
[transport.md](../../../../docs/architecture/transport.md).

## Connections and dispatch

`backends.ts` owns the attached-backend registry. Each backend has one
`WSClient`, one `TransportHandle`, and independent session, hello, replay cursor,
watch, lease, and status state. HOME is the ordinary `HOME_BACKEND` entry and may
be absent on a standalone frontend. Keep attachment eager and independent of
visibility.

Issue RPCs and subscriptions through `resolveTransport`, never by importing the
HOME `wsClient` singleton. An explicit, indexed, or selected target that is not
attached must reject. Unknown entity ownership may use the sole execution
computer; with several computers it is ambiguous and must reject. No route falls
back to HOME. `all` is the only fan-out route.

`methodRoutes.ts` is generated by `methodgen`; do not edit it. `methodFamilies.ts`
owns entity families that signatures cannot infer. Typed list, create, fork, and
detail results teach `entityIndex.ts` ownership before returning to callers.
Higher `ownershipEpoch` wins; contradictory equal-epoch claims make routing
fail. An ownership move invalidates the old computer's reads and cached thread
state.

`withBackendTarget` pins a synchronous generated call. Capture and reapply the
same target for each later RPC after an `await`. Transport errors that report a
thread move are navigation evidence only; they do not authorize attaching a
computer or replaying the operation elsewhere.

## WebSocket lifecycle and replay

`wsClient.ts` owns connection attempts, RPC correlation, channel cursors, replay,
and reconnect state. Every transport failure rejects as `DisconnectedError` and
keeps useful close and cause detail in `message`, because most callers surface
that field. Wrap connect-stage errors into the same class. Unknown additive wire
input is expected across rolling upgrades: count and debug-log it, but do not
throw, warn, advance a cursor from malformed input, or partially apply a malformed
batch.

Per-channel cursors are scoped to a server `launchId`. Seed missing cursors from
`replayBaseline`, preserve existing cursors within a launch, and clear them when
the launch changes. Normalize only a legacy `gap:true` frame with missing `seq`
to zero; other missing sequences are invalid.

Live frames may overtake replay. `replayBuffer.ts` orders each channel through
the completion marker before cursor deduplication. Bound buffered entries and
payload bytes; overflow discards buffered payloads and requests authoritative
snapshots. Snapshot recovery starts after the buffer drains. Replay completion
has its own deadline and only a socket that completes replay may reset backoff.

Honor explicit gaps before deduplication because a restart marker may have a
lower sequence than the old cursor. Forward skips on entity-filtered channels
are not inferred as gaps after this client has sent a watch set; withheld frames
legitimately consume sequence numbers. Explicit server gaps still recover.

Watches are absolute per connection and are sent before replay on reconnect.
`setWatchedThreadsEverywhere` splits known thread IDs by owner and sends unknown
owners to every attached backend. Lease state describes platform suspension,
not page visibility, and must be restated independently of watches.

The complete replay, gap, watch, and lease contracts are in
[transport.md](../../../../docs/architecture/transport.md#event-replay-and-filtering).

## Retries and connection state

Do not replay an RPC merely because its connection closed. The only mutation
retry list is `RETRY_ON_TRANSIENT_CLOSE`; an entry requires a backend-enforced
durable request ID and must resend the identical frame. Step-up retry is separate:
the backend already refused the first attempt before the one retry.

Terminal `unauthorized` and `pairing-required` states clear only from evidence,
such as user-triggered reconnect or a successful attempt past the condition.
Passive RPC demand must not restart a terminal ladder. Prolonged failure may
enter dormant cadence, but explicit demand and platform resume probe immediately.
A background native lease schedules no probes and active resume reuses the
existing queued attempt.

After resume, an open socket must receive a frame before recent outbound RPCs can
justify keeping it. Lifecycle resume timestamps do not count as network traffic.
Keep `lastConnectedAt` on inbound bytes or open, using the frontend clock.

## Credentials, grants, and step-up

`deviceSession.ts` is the only writer of paired session credentials. Preserve
unknown stored fields and distinguish absent grants from an explicit empty grant
set. Renewal of a single-use secret is single-flight across tabs through
`renewalLease.ts`; re-read stored state inside the lease so the losing tab adopts
the winner's result. Permanent known refusals may retire a pairing. Generic 401s,
unknown reasons, timeouts, rate limits, and intermediary failures may not.

When a stored paired session exists, socket and auth requests never fall back to
an ambient local-page identity. A keyed device whose private key is missing must
clear that unusable session rather than mint a replacement key or send a bare
identifier. `deviceKey.ts` generates only during enrollment and stores the
non-extractable P-256 key in IndexedDB. Plain HTTP clients may lack WebCrypto,
WebAuthn, Web Locks, UUID, or clipboard APIs; feature-test each API at runtime.

Scope state in `scopes.ts` is per backend and reactive. `host` applies only to
HOME. Carried desktop sessions use authenticated `sessionScopes`; missing grant
metadata means unknown legacy behavior, not full access. A feature capability
from hello is compatibility information and never authorization.

`wsClient.ts` intercepts `step_up_required` once and `stepUp.ts` performs the
ceremony on the same handle that refused. Ceremonies serialize and do not share
tokens. The retry consumes the token at frame construction and bypasses the
interceptor, so it cannot loop. Do not add per-call wrappers. Only user-initiated
writes may carry `//ao:stepup`; a passive read must never raise an authenticator.

## Bootstrap, identity, and native routes

Bootstrap publishes into leaf modules rather than importing the backend registry,
which would create a module-initialization cycle. Per-backend identity is keyed by
registry ID and must update on bootstrap refresh or window synchronization. Empty
identity fields disable replica use; they are not wildcards.

Personal introductions and connection activation are generation-bound. After an
async probe, recheck the pending pairing, session, exclusion, and removal state
before storing trust or attaching. Durable removal hints must not be evicted to
make enrollment succeed.

Native route selection keeps endpoint, TLS pin, credential, and pairing identity
bound to the same computer and request snapshot. A route change never changes
entity ownership or authorizes replaying a failed operation. Attachment tickets
and bytes use the captured thread owner through `backendTransferUrl`. See
[computer-routes.md](../../../../docs/architecture/computer-routes.md).

## Wire evolution and validation

`frames.ts` mirrors `internal/transport/frame.go`; update both sides together.
Evolve frames additively and tolerate unknown fields, frame types, channels, and
capabilities. Validate structured input before it can affect routing, cursors,
credentials, or persistent state.

Tests that stage HOME use `__attachBackendForTest(HOME_DESCRIPTOR, client)` and
reset through `__resetBackendsForTest`. Keep multi-backend tests distinct from
HOME-only tests: they must prove missing-target rejection, unknown-owner
ambiguity, per-backend replay and grant isolation, attachment after boot, and
rejection of stale asynchronous results.
