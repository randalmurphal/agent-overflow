# internal/theme/

Owns `<configDir>/themes/` — the client-side theme directory: the theme
files, the appearance selection, and the generated reference artifacts
seeded beside them. Spec: `docs/specs/theme-system.md` §7 "Phase 2/3
concrete contract".

## Layout

- `theme.go` — `Appearance` / `File` / `Files` wire shapes,
  `Service{Files, SetAppearance, EnsureBoot}` (atomic write under a
  private mutex), `NormalizeAppearance`, `ParseHexColor`, and the
  free function `WindowBackground(configDir)`.
- `assets/theme.schema.json`, `assets/TOKENS.md` — GENERATED by
  `frontend/scripts/generate-theme-reference.mjs` from the frontend
  token registry and committed. Embedded with `//go:embed assets/*`
  and refreshed into the user's themes directory at boot.

## Go never parses a theme file

`File.Raw` is the file's bytes verbatim. The token vocabulary lives in
`frontend/src/lib/theme/tokenRegistry.ts`; a backend that understood the
format would be a second definition of it, drifting silently the first
time the frontend grows a token (root `CLAUDE.md` principle 1). Only
`appearance.json` is typed here — four scalar fields, three of them an
enum or an id, one a hex color the NATIVE window needs.

That is also why validation splits the way it does: the backend refuses
a malformed *selection* loudly (`SetAppearance` returns an error the
user sees), while a malformed *token value* is the frontend's to skip
per-token with a visible warning.

## Warnings are data

`Files.Warnings` rides the RPC result beside a fully usable answer. A
theme file that is oversized, unreadable, or named something that cannot
be an id is skipped and explained; the directory being absent is not a
problem at all (fresh install). Nothing here logs-and-swallows: the
symptom of a silent skip is "my theme does nothing", which the user
cannot debug.

## Rules that hold across the package

- The generated artifacts are refreshed from the embedded copies on
  every boot, absent OR merely different. They document THIS build's
  vocabulary; local edits are expected to be lost and both files say so
  in their first lines.
- `appearance.json` is seeded only when absent, and that is the one
  moment the retiring `settings.theme` value is consulted
  (`EnsureBoot(legacyMode)`). The package never imports `settings` —
  the caller reads the legacy value and passes it.
- Theme ids are filename stems matching `^[a-z0-9][a-z0-9-]{0,63}$`.
  Anchored and bounded so an id can never escape the directory or reach
  the frontend as something that is not a CSS-safe identifier.
- Every write goes through `internal/atomicfile` (temp + fsync + rename,
  0600/0700) rather than a local copy of that dance. Its temp name is
  `<base>.tmp-NNNNN`, so an appearance write lands as
  `appearance.json.tmp-2148294417` — whose EXTENSION is `.tmp-2148294417`,
  not `.json`, which is what keeps it outside the `*.json` set the watcher
  (`app_theme_watcher.go`) reacts to. That property belongs to atomicfile's
  naming, not to this package, so it is pinned from the watcher side
  (`TestThemeWatcherIgnoresAtomicfileTempNames`). Self-write suppression is
  a backstop for the DESTINATION name, not the temp file.
- `Files()` is bounded three ways, and only the first is about one file:
  `MaxThemeFileBytes` per file (read through an `io.LimitReader`, so an
  oversize file is never fully loaded), `MaxThemeFilesBytes` and
  `MaxThemeFiles` over the whole listing. The aggregate caps stop the
  listing outright with one warning — past them the directory is not a
  themes directory any more, and the answer's size has to be a property of
  the format rather than of whatever is in the directory.
- The mutex covers the pending-boot retry and a `dir` snapshot only. The
  listing and the file reads run UNLOCKED, so a themes directory on a
  wedged filesystem cannot block `SetAppearance` — an interactive write
  must never queue behind a background read.
- A boot that could not seed `appearance.json` is REMEMBERED
  (`bootPending` / `pendingLegacy`) and retried from the next `Files()`.
  The retiring `settings.theme` value is dropped by the next settings
  write whether or not the seed succeeded, so the failed boot is the only
  thing still holding the user's light/dark choice — see
  `internal/settings/AGENTS.md` §Retired fields.

## Anti-patterns

- Do NOT add color math, palette resolution, or a token model here.
  Resolution is one `<style id="user-theme">` rewrite on the frontend.
- Do NOT make `WindowBackground` do more work. It runs on the desktop
  boot path before the App exists; it is one small file read and every
  failure answers `""` so the caller keeps its compiled-in fallback.
- Do NOT hand-edit `assets/*`. Regenerate them.
