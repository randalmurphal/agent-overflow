# `internal/agentmeta`

Owns how a user row's message is attributed to an agent or to the app, and
how a person reads such a row. It depends on no store, so `internal/store`
derives an agent row's thread-find text (`Headlines`, `ReadableWakeText`)
from the same rule the timeline renders the row by. `internal/usermessage`
owns the rest of the row's meta and the constructors that write these
messages; `usermessage.Meta.Agent` is the part of its meta read here.

`Describe` is the one reading of an agent's row for a person: the timeline
(through `ProjectMeta`, which `usermessage.ProjectRowMeta` serves), the
Edits selector, `thread_show` and the store's find text all take it. It
checks facts against the text and shows a message whose facts do not
describe it whole. Only `legacy.go` reads text, and only the shapes main
wrote; `testdata/served_rows.json` is what the frontend renders,
regenerated by `TestServedRowsFixture`.

A report kind is one entry in `reportKinds` (`report.go`): its row's
category, labels, sender, badge and body presentation, its `thread_show`
name and its wire sender line. A client receives it resolved on the
report's attribution (`OriginWake.Served`, `ReportDescriptor`), from
`ProjectMeta` and the queue's items; the frontend adds only an icon.
Adding a kind is that entry and, for a new icon, one in
`AgentMessageRow.svelte`.

Tests are an external package (`agentmeta_test`) so they can write rows
through `usermessage`'s constructors; `export_test.go` defines the
test-only report kind.
